# 更多玩法和提升

<AuthorByline date="2026-10-18" category="智能车" />

## 编码器的玩法

目前，大家最常用的是编码器的测速功能：每隔一个固定周期读取编码器记录的脉冲数，然后将计数清零，为下一周期做准备。

换个思路，如果不清除计数，而是让脉冲数持续累加，那么小车行驶一段距离后，就会得到相应的累计脉冲数。在相同条件下，行驶距离相同，对应的脉冲数也基本相同。这样，编码器就相当于一个“里程计”，可以用来估算小车行驶的距离。

## 陀螺仪的玩法

陀螺仪 Z 轴反馈的是角速度 ω。对角速度进行积分，就可以得到偏航角的变化量。以起始朝向为 0°，当小车向右转过 90° 时，偏航角也会产生约 90° 的变化。由此，就可以观察车身相对于起始方向的朝向。

<details>

<summary>示例：角速度怎样累加成偏航角</summary>

```c
#include "zf_common_headfile.h"
#include "imu.h"
#include <math.h>

float example_yaw_deg = 0.0f;
void GyroExample_500us(void)
{
    const float dt_s = 0.0005f;  // 实际调用间隔：500 μs
    imu660rb_get_gyro();
    gyro_filter_main();          // 零偏校准、去零偏、低通滤波
    if (!g_gyro_f.cali_done) return;
    float rate_dps = imu660rb_gyro_transition(gyro_filtered[2]);
    if (fabsf(rate_dps) < 0.38f) rate_dps = 0.0f;
    example_yaw_deg += rate_dps * dt_s;
    while (example_yaw_deg > 180.0f) example_yaw_deg -= 360.0f;
    while (example_yaw_deg < -180.0f) example_yaw_deg += 360.0f;
}
```

## 提速的思考

提高目标速度 vtarget 后，小车可能会出现转向不及时的情况。此时，调参是必要的，但不能只靠调参。还要检查代码中是否存在低速下合理、高速下却不再适用的参数或逻辑，例如前瞻位置、差速限幅等。这也是为什么要自己理解和设计代码，而不能完全交给 AI。

排查完这些问题后，还可以继续思考如何提高响应速度。例如，分析摄像头帧率和控制中断周期对电机响应的影响；也可以尝试其他控制方案，如串级增量式 PI、位置式 PI，或前馈速度环。

除了优化控制代码，也可以在图像处理方面大胆调整参数，尝试不同的拉线方案。

总之，提速需要配合相关参数的调整，并理解它们随速度变化的规律。如果反复调参仍然无法解决问题，就应考虑优化代码。优化并不意味着让代码变得更复杂，而是先找到问题，再有针对性地尝试解决方案。

## 测运行时间

可以分别测量图像处理代码和控制代码的运行时间。如果图像处理耗时过长，就难以进一步提高帧率。

```c
/* 主循环中，沿用原来的图像处理位置 */
if (mt9v03x_finish_flag == 1)
{
    mt9v03x_finish_flag = 0;
    system_start();                 // 记录开始时刻
    image_main();                   // 处理这一帧
    runtime.image_Runtime = system_getval_us();
}
```
